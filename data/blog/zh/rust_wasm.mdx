### 前言

Rust 笔记基础系列已经完结了（20 篇！），但光学语法不写项目等于没学。作为前端开发，**WebAssembly（wasm）** 是 Rust 落地到你日常工作中最自然的路径——不需要转行写后端，直接在浏览器里用 Rust 的性能优势。

这篇不是泛泛而谈"wasm 是什么"，而是从零开始，手把手写一个完整的 Rust + wasm 项目，让你看到**从 Rust 代码到浏览器调用**的全链路。

<DividerLarge />

## WebAssembly 到底是什么

先用一句话说清楚：WebAssembly 是一种**可以在浏览器中运行的低级字节码格式**，它不是要取代 JavaScript，而是做 JS 不擅长的事——计算密集型任务。

### 谁在用 wasm

这不是实验室技术，已经有大量生产级应用：

- **Figma** — 用 C++ 编译为 wasm，实现浏览器内的高性能图形编辑
- **Google Earth** — 地球渲染引擎跑在 wasm 上
- **Photoshop Web** — Adobe 把 Photoshop 搬到了浏览器
- **1Password** — 密码加密逻辑用 Rust + wasm
- **Cloudflare Workers** — 边缘计算运行 wasm 模块

> [!TIP]
> 一个判断标准：如果你的 JS 代码里有大量的 `for` 循环在做数值计算，或者用户抱怨"页面卡了"，那这部分逻辑就值得考虑用 wasm 替代。

<DividerSmall />

### Rust 为什么适合编译到 wasm

不是所有语言都适合编译到 wasm，Rust 特别适合有几个原因：

| 特性 | 为什么重要 |
|------|-----------|
| 无 GC | wasm 没有内置垃圾回收，Rust 不需要 GC，天然契合 |
| 编译产物小 | Rust 编译的 wasm 文件通常只有几十 KB，比 Go 编译的小一个数量级 |
| `wasm-bindgen` 生态 | Rust 有最成熟的 wasm 工具链，JS/Rust 互调非常方便 |
| 安全性 | 内存安全保证延伸到 wasm，不会出现缓冲区溢出 |
| 性能可预测 | 没有 GC 停顿，性能接近原生 C/C++ |

### 创建项目

```bash

# 创建一个 Rust 库项目
cargo new --lib wasm-hello
cd wasm-hello

```

编辑 `Cargo.toml`：

```toml

[package]
name = "wasm-hello"
version = "0.1.0"
edition = "2021"

[lib]
crate-type = ["cdylib"]  # 编译为动态链接库（wasm 需要）

[dependencies]
wasm-bindgen = "0.2"      # Rust ↔ JS 绑定

[dependencies.web-sys]
version = "0.3"
features = ["console"]     # 按需启用浏览器 API

```

> [!NOTE]
> `crate-type = ["cdylib"]` 告诉编译器生成一个可以被外部（浏览器/Node.js）加载的动态库，而不是 Rust 内部使用的静态库。

## 第一个 wasm 函数

### Rust 端

编辑 `src/lib.rs`：

```rust

use wasm_bindgen::prelude::*;

// 导入 JS 的 alert 函数
#[wasm_bindgen]
extern "C" {
    fn alert(s: &str);
}

// 导出给 JS 调用的函数
#[wasm_bindgen]
pub fn greet(name: &str) {
    alert(&format!("Hello, {}! 这条消息来自 Rust + wasm 🦀", name));
}

// 导出一个纯计算函数
#[wasm_bindgen]
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}

```

`#[wasm_bindgen]` 是一切的核心——这个宏自动生成 Rust 和 JS 之间的胶水代码：
- `extern "C"` 块：声明要从 JS 导入的函数
- `pub fn` 上的标注：将 Rust 函数导出给 JS 使用

### 编译

```bash

wasm-pack build --target web

```

## 实战：图像灰度处理

Hello World 太简单了，来个真实场景——**用 Rust + wasm 处理图像**，这是 wasm 最经典的应用场景之一。

### 为什么图像处理适合 wasm

一张 1920×1080 的图片有 **2,073,600 个像素**，每个像素 4 个通道（RGBA），总共需要处理 **800 多万次**运算。这种密集的逐像素计算正是 JS 的弱项和 wasm 的强项。

### Rust 端：灰度转换

```rust

use wasm_bindgen::prelude::*;

/// 将 RGBA 图像数据转换为灰度
/// pixels: 原始像素数据（RGBA 格式，每 4 个 u8 为一个像素）
/// 返回处理后的像素数据
#[wasm_bindgen]
pub fn grayscale(pixels: &[u8]) -> Vec<u8> {
    let mut result = pixels.to_vec();

    for chunk in result.chunks_exact_mut(4) {
        let r = chunk[0] as f32;
        let g = chunk[1] as f32;
        let b = chunk[2] as f32;

        // ITU-R BT.709 标准灰度权重
        let gray = (0.2126 * r + 0.7152 * g + 0.0722 * b) as u8;

        chunk[0] = gray; // R
        chunk[1] = gray; // G
        chunk[2] = gray; // B
        // chunk[3] 保持不变（Alpha 通道）
    }

    result
}

/// 调整亮度
/// factor: -255 到 255
#[wasm_bindgen]
pub fn adjust_brightness(pixels: &[u8], factor: i32) -> Vec<u8> {
    let mut result = pixels.to_vec();

    for chunk in result.chunks_exact_mut(4) {
        for i in 0..3 {
            let val = chunk[i] as i32 + factor;
            chunk[i] = val.clamp(0, 255) as u8;
        }
    }

    result
}

/// 反色
#[wasm_bindgen]
pub fn invert(pixels: &[u8]) -> Vec<u8> {
    let mut result = pixels.to_vec();

    for chunk in result.chunks_exact_mut(4) {
        chunk[0] = 255 - chunk[0];
        chunk[1] = 255 - chunk[1];
        chunk[2] = 255 - chunk[2];
    }

    result
}

```

### JS 端：Canvas 集成

```javascript

import init, { grayscale, adjust_brightness, invert } from './pkg/wasm_hello.js';

async function main() {
  await init();

  const canvas = document.getElementById('canvas');
  const ctx = canvas.getContext('2d');

  // 加载图片到 canvas
  const img = new Image();
  img.src = 'photo.jpg';
  img.onload = () => {
    canvas.width = img.width;
    canvas.height = img.height;
    ctx.drawImage(img, 0, 0);
  };

  // 灰度按钮
  document.getElementById('btn-gray').onclick = () => {
    const imageData = ctx.getImageData(0, 0, canvas.width, canvas.height);

    console.time('wasm grayscale');
    const result = grayscale(imageData.data);
    console.timeEnd('wasm grayscale');

    imageData.data.set(result);
    ctx.putImageData(imageData, 0, 0);
  };

  // 亮度按钮
  document.getElementById('btn-bright').onclick = () => {
    const imageData = ctx.getImageData(0, 0, canvas.width, canvas.height);
    const result = adjust_brightness(imageData.data, 50);
    imageData.data.set(result);
    ctx.putImageData(imageData, 0, 0);
  };

  // 反色按钮
  document.getElementById('btn-invert').onclick = () => {
    const imageData = ctx.getImageData(0, 0, canvas.width, canvas.height);
    const result = invert(imageData.data);
    imageData.data.set(result);
    ctx.putImageData(imageData, 0, 0);
  };
}

main();

```

  description="代码逻辑几乎一样——但 wasm 版本处理百万级像素时快 2-5 倍"
/>

在 1920×1080 图片上的实际测试数据（Chrome，M1 MacBook）：

| 操作 | JavaScript | Rust wasm | 提升 |
|------|-----------|-----------|------|
| 灰度转换 | ~12ms | ~3ms | **4x** |
| 亮度调整 | ~8ms | ~2ms | **4x** |
| 反色处理 | ~6ms | ~1.5ms | **4x** |
| 高斯模糊（5×5） | ~180ms | ~35ms | **5x** |

> [!TIP]
> 单次处理 12ms vs 3ms 似乎差别不大。但如果是实时视频处理（每秒 30 帧），JS 版本需要 360ms/s（有卡顿风险），wasm 版本只需要 90ms/s（游刃有余）。

### 与 Vite 集成

Vite 对 wasm 的支持非常好，安装 `vite-plugin-wasm`：

```bash

npm install vite-plugin-wasm vite-plugin-top-level-await

// vite.config.js
import { defineConfig } from 'vite'
import wasm from 'vite-plugin-wasm'
import topLevelAwait from 'vite-plugin-top-level-await'

export default defineConfig({
  plugins: [wasm(), topLevelAwait()],
})

```

然后在代码中直接 import：

```javascript

import init, { grayscale } from 'wasm-hello'

// 在组件中使用
await init()

```

### 与 React 集成

```jsx

import { useEffect, useRef, useState } from 'react'
import init, { grayscale } from 'wasm-hello'

function ImageProcessor() {
  const [wasmReady, setWasmReady] = useState(false)
  const canvasRef = useRef(null)

  useEffect(() => {
    init().then(() => setWasmReady(true))
  }, [])

  const handleGrayscale = () => {
    if (!wasmReady) return
    const canvas = canvasRef.current
    const ctx = canvas.getContext('2d')
    const imageData = ctx.getImageData(0, 0, canvas.width, canvas.height)
    const result = grayscale(imageData.data)
    imageData.data.set(result)
    ctx.putImageData(imageData, 0, 0)
  }

  return (
    <div>
      <canvas ref={canvasRef} />
      <button onClick={handleGrayscale} disabled={!wasmReady}>
        灰度处理
      </button>
    </div>
  )
}

```

> [!WARNING]
> `init()` 是异步的（需要加载 .wasm 文件），务必在 `useEffect` 中调用并确保加载完成后再使用 wasm 函数。

## wasm-bindgen 进阶

### 传递复杂类型

基础类型（数字、字符串、布尔）可以直接传递。但如果需要传递结构体或对象，需要用 `#[wasm_bindgen]` 标注：

```rust

use wasm_bindgen::prelude::*;
use serde::{Serialize, Deserialize};

#[wasm_bindgen]
#[derive(Serialize, Deserialize)]
pub struct ImageConfig {
    width: u32,
    height: u32,
    brightness: i32,
    contrast: f32,
}

#[wasm_bindgen]
impl ImageConfig {
    #[wasm_bindgen(constructor)]
    pub fn new(width: u32, height: u32) -> ImageConfig {
        ImageConfig {
            width,
            height,
            brightness: 0,
            contrast: 1.0,
        }
    }

    #[wasm_bindgen(getter)]
    pub fn width(&self) -> u32 {
        self.width
    }

    #[wasm_bindgen(setter)]
    pub fn set_brightness(&mut self, val: i32) {
        self.brightness = val.clamp(-255, 255);
    }
}

```

在 JS 端就可以像普通 class 一样使用：

```javascript

const config = new ImageConfig(1920, 1080);
config.brightness = 50;
console.log(config.width); // 1920

```

<DividerSmall />

### 调用浏览器 API

通过 `web-sys` crate 可以直接在 Rust 中调用浏览器的 DOM API：

```rust

use wasm_bindgen::prelude::*;
use web_sys::console;

#[wasm_bindgen]
pub fn log_to_console(msg: &str) {
    console::log_1(&msg.into());
}

#[wasm_bindgen]
pub fn get_performance_now() -> f64 {
    web_sys::window()
        .expect("no window")
        .performance()
        .expect("no performance")
        .now()
}

```

> [!NOTE]
> `web-sys` 的每个 API 都是一个 feature flag，需要在 `Cargo.toml` 中按需启用。这样可以避免引入不需要的代码，保持 wasm 文件体积最小。

### 最佳实践清单

| 实践 | 说明 |
|------|------|
| 粗粒度 API | 一次传一大块数据，不要频繁跨边界调用 |
| Release 编译 | 始终用 `--release`，Debug 模式的 wasm 慢 10 倍以上 |
| 按需启用 web-sys | 只开启你用到的 feature，控制体积 |
| 异步初始化 | wasm 加载是异步的，要处理好加载状态 |
| 错误处理 | Rust 的 panic 会变成 JS 异常，用 `console_error_panic_hook` 获取可读的错误信息 |
| 类型安全 | 利用生成的 `.d.ts` 文件，在 TypeScript 项目中获得完整的类型提示 |

## 总结

作为一个前端开发，Rust + WebAssembly 给你打开了一扇新的大门：

- **不需要切换职业赛道** — 你依然写前端，只是在性能瓶颈处用 Rust 加速
- **工具链已经成熟** — `wasm-pack` + `wasm-bindgen` 让编译和调用丝滑无比
- **TypeScript 友好** — 自动生成 `.d.ts`，和你的 TS 项目无缝集成
- **渐进式采用** — 不需要重写整个应用，只把计算密集的部分抽出来用 Rust 实现

如果你跟着 Rust 笔记系列走到了这里，你已经具备了写 wasm 的全部 Rust 知识。剩下的就是动手——找一个你项目中跑得慢的 JS 函数，用 Rust 重写它，编译成 wasm，然后看着 `console.time` 打印出来的数字变小。

那种感觉，很爽。
