### 前言
介绍 Rust 的变量前，我们已经知道 Rust 的内存安全特性，具体在变量上是如何体现出来的呢，让我一一道来


### 手动设置变量可变性
> 在其它大多数语言中，要么只支持声明可变的变量，要么只支持声明不可变的变量（例如函数式语言），前者为编程提供了灵活性，后者为编程提供了安全性，而 Rust 比较野，选择了两者我都要，既要灵活性又要安全性。
能想要学习 Rust，说明我们的读者都是相当有水平的程序员了，你们应该能理解一切选择皆是权衡，那么两者都要的权衡是什么呢？这就是 Rust 开发团队为我们做出的贡献，两者都要意味着 Rust 语言底层代码的实现复杂度大幅提升，因此 Salute to The Rust Team!
除了以上两个优点，还有一个很大的优点，那就是运行性能上的提升，因为将本身无需改变的变量声明为不可变在运行期会避免一些多余的 runtime 检查。[^1]

### 变量命名

### 变量绑定

```rust
let a = "hello world";
```

这段代码在 Rust 中，我们可以说 将 "hello world" 绑定给了 a 变量，通过前篇的介绍可以知道，Rust 有 **所有权** 的概念，要知道，一切皆为权衡，所有权的设计是为了内存安全的特性，同时也让无GC成为了可能，在上述的变量绑定过程中，
a就成为了 "hello world" 的主人，同时默认不可变，如果想要后续变更 a 变量，我们则需要这样写

```rust
let mut a = "hello world";
```

如果修改不可变变量，`cargo check` 将会抛出错误

### 使用下划线忽略未使用的变量

如果某个变量未被使用，rust编译器会抛出warn提醒，这种情况我们将变量名追加一个下划线前缀即可，这样编译器就知道这个变量可以被忽略了

```rust

let a: &str = "hello world";

//执行编译
cargo check

warning: unused variable: `a`
 --> src/main.rs:5:9
  |
5 |     let a: &str = "hello world";
  |         ^ help: if this is intentional, prefix it with an underscore: `_a`
  |
  = note: `#[warn(unused_variables)]` on by default

warning: `hello_world` (bin "hello_world") generated 1 warning
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.03s

//调整一下
let _a: &str = "hello world";

```



### 变量解构

Rust 支持类似 `JavaScript` ES6 解构赋值的语法，可以从复合类型中一次性提取多个值：

```rust

let (mut a, b): (u8, u8) = (0, 1);
// a 是可变的，b 是不可变的
a = 2;

```

注意看，解构时可以对单个变量独立设置 `mut`，这在 JS 中是做不到的（JS 的 `const` 和 `let` 是整条语句级别的）。

再看一个更实用的例子：

```rust

struct Point {
    x: i32,
    y: i32,
}

fn main() {
    let point = Point { x: 10, y: 20 };

    // 解构结构体
    let Point { x, y } = point;
    println!("x = {}, y = {}", x, y);

    // 也可以在解构时重命名
    let Point { x: px, y: py } = Point { x: 30, y: 40 };
    println!("px = {}, py = {}", px, py);
}

```

解构在 Rust 中的使用场景非常广泛，后续学到 `match` 模式匹配和函数参数时会大量用到。


### 变量遮蔽（Shadowing）

这是 Rust 中一个很有意思的特性，你可以用 `let` 重新声明一个同名变量来"遮蔽"前一个变量：

```rust

fn main() {
    let x = 5;
    // 遮蔽前一个 x
    let x = x + 1;
    // 再次遮蔽
    let x = x * 2;
    println!("x = {}", x); // 输出：x = 12
}

```

乍一看这和 `mut` 有点像，但它们有本质区别：
1. **遮蔽是创建了一个全新的变量**，只是恰好同名，甚至可以改变类型
2. **mut 是同一个变量的可变绑定**，类型不能改变

这意味着遮蔽可以做到 `mut` 做不到的事，比如改变类型：

```rust

// 这样是可以的 ✅
let spaces = "   ";        // &str 类型
let spaces = spaces.len(); // usize 类型，完全不同的类型

// 但这样不行 ❌
let mut spaces = "   ";
spaces = spaces.len(); // 编译错误！不能把 usize 赋给 &str

```

对比 `JavaScript`，遮蔽有点像在不同的 `{}` 块中用 `let` 声明同名变量，但 Rust 允许在同一作用域内进行遮蔽，这让代码中的数据类型转换变得非常简洁，不需要起 `spaces_str`、`spaces_len` 这样的临时变量名。
