### 前言

上篇聊完了基础类型，这篇我们来碰 Rust 最硬的骨头——**所有权（Ownership）**。

如果说前面的内容还能靠其他语言的经验带一带，那所有权就是 Rust 独有的概念了。它不是语法糖，不是设计模式，而是一套 **编译期的内存管理规则**——Rust 之所以不需要垃圾回收器（GC），同时又能保证内存安全，靠的就是这套规则。

对于写惯了 `JavaScript` 的同学来说，内存管理一直是"引擎帮你搞定"的事，你甚至不需要知道变量存在栈上还是堆上。但在 Rust 中，你必须理解这些，因为所有权规则就建立在栈和堆的区别之上。

<DividerSmall />

### 先聊聊栈和堆

在深入所有权之前，必须先搞清楚栈（Stack）和堆（Heap）的区别，因为所有权的行为取决于数据存储在哪里。

**栈（Stack）**：后进先出，分配和释放极快。所有存储在栈上的数据必须有已知的、固定的大小。比如 `i32` 占 4 字节，`bool` 占 1 字节，编译期就能确定。

**堆（Heap）**：用于存放编译期大小未知或可能变化的数据。你向操作系统申请一块内存，系统找到一块够大的空间标记为已使用，然后返回一个指针。这个指针本身是固定大小的，存在栈上，但它指向的数据在堆上。

打个比方：栈就像食堂的餐盘架，你只能从最上面取和放，速度飞快；堆就像仓库，你得找管理员登记、分配货位，慢一些但空间更灵活。

```rust

let x = 5;           // i32，固定大小，存在栈上
let s = String::from("hello"); // String，内容可变长，数据存在堆上，栈上存指针

```

在 JS 中，基本类型（number、boolean）存在栈上，引用类型（object、array）存在堆上——这点其实和 Rust 类似，只是 JS 有 GC 帮你自动回收堆内存，而 Rust 用所有权规则来管理。

<DividerSmall />

### 所有权三条规则

Rust 的所有权系统很简洁，只有三条规则：

1. **Rust 中的每一个值都有一个所有者（owner）**
2. **值在任一时刻有且只有一个所有者**
3. **当所有者离开作用域，值将被丢弃（drop）**

就这三条，没了。但它们的推论覆盖了整个内存管理。

```rust

{
    let s = String::from("hello"); // s 从这里开始有效，s 是 "hello" 的所有者
    // 可以使用 s
} // 这个作用域结束，s 离开作用域，Rust 自动调用 drop 函数释放堆内存

```

如果你学过 C++，这就是 RAII（Resource Acquisition Is Initialization）模式——资源的生命周期绑定到变量的作用域。离开作用域自动释放，不需要手动 `free`，也不需要 GC。

<DividerSmall />

### 移动（Move）：所有权转移

这是最容易让新手困惑的地方。先看一段看起来很正常的代码：

```rust

let s1 = String::from("hello");
let s2 = s1;

println!("{}", s1); // ❌ 编译错误！

```

在 JS 中，这段代码完全没问题——`s1` 和 `s2` 都指向同一个对象。但在 Rust 中，`let s2 = s1` 并不是复制，而是 **移动（move）**——所有权从 `s1` 转移到了 `s2`，之后 `s1` 就失效了。

为什么要这么设计？回想所有权的第二条规则："值在任一时刻有且只有一个所有者"。如果 `s1` 和 `s2` 同时拥有那块堆内存，当它们都离开作用域时，同一块内存会被释放两次——这就是 C/C++ 中臭名昭著的 **double free** 错误。

Rust 用移动语义在编译期就杜绝了这个问题。

```
栈内存：
s1 -> [ptr, len: 5, capacity: 5]   （s1 赋值给 s2 后失效）
s2 -> [ptr, len: 5, capacity: 5]   （s2 成为新的所有者）

堆内存：
[h, e, l, l, o]   （只有一个所有者，离开作用域时只释放一次）
```

**注意**：移动只发生在堆数据上。对于栈上的简单类型（整数、布尔、浮点、字符），赋值时会直接复制，因为复制成本极低：

```rust

let x = 5;
let y = x;  // 复制，不是移动
println!("{}", x); // ✅ 完全没问题，x 仍然有效

```

这类实现了 `Copy` trait 的类型在赋值时会自动复制，而不是移动。后面学到 trait 时会详细展开。

### 克隆（Clone）：深拷贝

如果你确实需要深拷贝一份堆数据，可以使用 `clone` 方法：

```rust

let s1 = String::from("hello");
let s2 = s1.clone(); // 深拷贝堆上的数据

println!("s1 = {}, s2 = {}", s1, s2); // ✅ 两个都有效

```

`clone` 会在堆上复制一份完整的数据，所以 `s1` 和 `s2` 各自拥有独立的内存。代价是性能开销——对于大数据来说，深拷贝很昂贵。所以 Rust 默认用移动而不是复制，让你在需要复制的地方显式调用 `clone`，避免隐式的性能损耗。

对比 JS：`Object.assign()` 是浅拷贝，`structuredClone()` 是深拷贝，但 JS 不会阻止你对原对象的访问。Rust 更激进——移动之后原变量直接不可用。

<DividerSmall />

### 函数与所有权

把值传给函数，和赋值给变量一样，会发生移动或复制：

```rust

fn main() {
    let s = String::from("hello");
    takes_ownership(s);       // s 的所有权移动到函数中
    // println!("{}", s);     // ❌ s 已经失效

    let x = 5;
    makes_copy(x);            // x 是 i32，实现了 Copy，所以是复制
    println!("{}", x);        // ✅ x 仍然有效
}

fn takes_ownership(some_string: String) {
    println!("{}", some_string);
} // some_string 离开作用域，drop 被调用，内存被释放

fn makes_copy(some_integer: i32) {
    println!("{}", some_integer);
} // some_integer 离开作用域，没什么特别的（栈上的值直接弹出）

```

同样，函数返回值也会转移所有权：

```rust

fn gives_ownership() -> String {
    let s = String::from("hello");
    s // 返回 s，所有权移动给调用者
}

fn main() {
    let s1 = gives_ownership(); // s1 获得所有权
    println!("{}", s1);         // ✅
}

```

如果每次调用函数都要转移所有权，用完再返回，那代码会非常啰嗦：

```rust

fn calculate_length(s: String) -> (String, usize) {
    let length = s.len();
    (s, length) // 不得不把 s 再还回去
}

fn main() {
    let s1 = String::from("hello");
    let (s2, len) = calculate_length(s1);
    println!("'{}' 的长度是 {}", s2, len);
}

```

这也太麻烦了。为了解决这个问题，Rust 提供了 **引用（Reference）**。

<DividerSmall />

### 引用与借用

引用允许你使用一个值但不获取其所有权，这叫做 **借用（Borrowing）**：

```rust

fn calculate_length(s: &String) -> usize { // s 是对 String 的引用
    s.len()
} // s 离开作用域，但因为它没有所有权，什么也不会发生

fn main() {
    let s1 = String::from("hello");
    let len = calculate_length(&s1); // &s1 创建一个引用，不转移所有权
    println!("'{}' 的长度是 {}", s1, len); // ✅ s1 仍然有效
}

```

`&` 符号就是引用，`&s1` 创建了一个指向 `s1` 的引用。函数参数 `s: &String` 表示"我借用一个 String，但我不拥有它"。

默认情况下，引用是 **不可变的**——你不能通过引用修改原始值：

```rust

fn change(s: &String) {
    s.push_str(", world"); // ❌ 编译错误！不能修改借用的值
}

```

<DividerSmall />

### 可变引用

如果确实需要通过引用修改值，需要使用 **可变引用**：

```rust

fn change(s: &mut String) {
    s.push_str(", world");
}

fn main() {
    let mut s = String::from("hello"); // 变量本身也必须是 mut
    change(&mut s);
    println!("{}", s); // "hello, world"
}

```

但可变引用有一个严格的限制：**在同一作用域中，对同一数据只能有一个可变引用**：

```rust

let mut s = String::from("hello");

let r1 = &mut s;
let r2 = &mut s; // ❌ 编译错误！不能同时有两个可变引用

println!("{}, {}", r1, r2);

```

这个限制是为了在编译期防止 **数据竞争（data race）**。数据竞争发生在：
- 两个或更多指针同时访问同一数据
- 至少一个指针在写入
- 没有同步机制

C/C++ 中数据竞争是运行时才会暴露的 bug，极难调试。Rust 直接在编译期把这条路堵死了。

同样，**不能同时有可变引用和不可变引用**：

```rust

let mut s = String::from("hello");

let r1 = &s;     // ✅ 不可变引用
let r2 = &s;     // ✅ 多个不可变引用没问题
let r3 = &mut s; // ❌ 有不可变引用时不能创建可变引用

println!("{}, {}, {}", r1, r2, r3);

```

逻辑很简单：如果有人正在读数据（不可变引用），你不能同时修改它（可变引用），否则读到的数据就不一致了。

但引用的作用域是从声明到 **最后一次使用**，而不是到花括号结束。所以这样是可以的：

```rust

let mut s = String::from("hello");

let r1 = &s;
let r2 = &s;
println!("{}, {}", r1, r2);
// r1 和 r2 在这之后就不再使用了，它们的作用域结束

let r3 = &mut s; // ✅ 此时没有不可变引用了
println!("{}", r3);

```

这个特性叫做 **NLL（Non-Lexical Lifetimes，非词法作用域生命周期）**，是 Rust 编译器的一个重要优化。

<DividerSmall />

### 悬垂引用

Rust 编译器保证引用永远不会是悬垂的（dangling）——即引用指向的内存已经被释放：

```rust

fn dangle() -> &String { // ❌ 编译错误
    let s = String::from("hello");
    &s // 返回 s 的引用，但 s 在函数结束时被释放了
}      // s 被 drop，引用指向了无效内存

```

在 C/C++ 中，返回局部变量的指针是一个经典的 bug——编译器不会阻止你，运行时也不一定崩溃，但你拿到的是一个指向已释放内存的野指针。Rust 在编译期就拒绝了这段代码。

正确的做法是直接返回 String，转移所有权：

```rust

fn no_dangle() -> String {
    let s = String::from("hello");
    s // 所有权移动给调用者，没有任何问题
}

```

<DividerSmall />

### 引用的规则总结

简单归纳一下引用的规则：

- **在任意时刻，你可以拥有以下之一**：一个可变引用 **或** 任意数量的不可变引用
- **引用必须始终有效**（不能悬垂）

这两条规则加上前面的所有权三条规则，就是 Rust 内存安全的全部基石。没有 GC，没有运行时开销，全靠编译器在编译期检查。

<DividerSmall />

### 小结

所有权是 Rust 的灵魂概念。第一次接触的时候一定会觉得"编译器管太多了"，各种报错让人崩溃。但一旦内化了这套规则，你会发现：

- **不会再有内存泄漏**——离开作用域自动释放
- **不会再有 use-after-free**——移动后原变量直接失效
- **不会再有 double free**——同一时刻只有一个所有者
- **不会再有数据竞争**——可变引用的排他性保证

这些在 C/C++ 中需要靠程序员自觉避免的问题，在 Rust 中全都被编译器拦截了。编译器是你最严格的代码审查员——它会让你编译的时候痛苦一点，但运行的时候安心很多。
